# نسخه برای پلتفرم دیگر (Repurposing)

یک محتوا را می‌شود برای چند پلتفرم دیگر دوباره نوشت. AI نسخهٔ تازه را برای پلتفرم و قالب هدف **از نو می‌سازد** (نه فقط کوتاه یا بلند کردن): ساختار، قلاب، طول، قالب‌بندی و دعوت به اقدام با مقصد جور می‌شود، ولی پیام، ادعاها و واقعیت‌های محتوای اصلی و اصول و واژه‌نامهٔ برند حفظ می‌شود.

## جریان

1. در صفحهٔ محتوا **«نسخه برای پلتفرم دیگر»** را بزنید، یک یا چند پلتفرم (تا ۶) را تیک بزنید. برای هر پلتفرم قالب پیش‌فرضش پر می‌شود (`PLATFORM_DEFAULT_FORMAT`، مثلاً ایکس ← رشته‌توییت، لینکدین ← مقاله، اینستاگرام ← کاروسل) و قابل تغییر است. جهت‌گیری اختیاری هم می‌توانید بنویسید («کوتاه‌تر و رسمی‌تر»).
2. برای هر هدف **یک محتوای جدید** (`GENERATING`) ساخته و یک کار AI صف می‌شود. این کار در مسیر درخواست انجام نمی‌شود و AI فقط در worker صدا زده می‌شود.
3. هر نسخه **یک محتوای مستقل** است: پیش‌نویس، بازبینی و تأیید ([21-review-workflow.md](21-review-workflow.md)) و برنامهٔ انتشار ([22-calendar-publishing.md](22-calendar-publishing.md)) خودش را دارد. کمپین و برچسب‌های اصلی به آن می‌رسد.
4. صفحهٔ محتوای اصلی کارت **«نسخه‌های پلتفرم‌ها»** را دارد (هر نسخه با پلتفرم، قالب و وضعیت) و صفحهٔ هر نسخه **«برگرفته از»** را.

محتوای **منتشرشده** هم قابل نسخه‌برداری است؛ قفل بودن فقط جلوی تغییر خودِ آن را می‌گیرد.

## مدل داده

- `Content.platform` (`Platform?`): پلتفرمی که محتوا برایش ساخته شده؛ `null` یعنی همان پلتفرم موضوع. **پلتفرم مؤثر** = `platform ?? topic.platform` (`effectivePlatform`). تقویم، جست‌وجو و فیلتر پلتفرم از همین استفاده می‌کنند.
- `Content.sourceContentId` ← محتوای اصلی (`ON DELETE SET NULL`؛ با حذف اصلی، نسخه‌ها می‌مانند).
- نوع کار تازه `REPURPOSE_CONTENT` در `AiJobType` (`ALTER TYPE ... ADD VALUE`). migration: `20261010090000_repurpose_content`.

## AI و کد

- پرامپت `repurpose_content` (در بک‌آفیس ← پرامپت‌ها قابل ویرایش؛ بدون ویرایش، پیش‌فرض داخل کد استفاده می‌شود). متغیرها: `language`، `topic`، `business`، `profile`، `principles`، `brand_docs`، `source` (پلتفرم، قالب و متن پیش‌نویس فعلیِ اصلی)، `target_platform`، `target_format` و `direction`. بلوک `topic` پلتفرمِ **هدف** را می‌نویسد.
- خروجی همان `ContentDraftResult` (عنوان، متن، هشتگ، CTA، یادداشت تولید و خودارزیابی) است و با Zod اعتبارسنجی می‌شود. `RepurposeContentRunner` نسخهٔ ۱ را می‌نویسد، وضعیت را `DRAFT` می‌کند و جهت‌گیری را به‌عنوان `feedback` نسخه نگه می‌دارد.
- مدل و effort این کار از «تنظیمات AI» جدا قابل انتخاب است (پیش‌فرض effort: متوسط).
- واژه‌نامهٔ برند همچنان با کد روی نسخهٔ تازه چک می‌شود ([16-business-profile-quality.md](16-business-profile-quality.md)).
- اگر محتوای اصلی پیش‌نویس نداشته باشد، کار بی‌retry شکست می‌خورد و محتوای تازه `FAILED` می‌شود.

## API

`POST /contents/:id/repurpose` ← **۲۰۲**، بدنه `{ targets: [{ platform, format? }], notes? }` (۱ تا ۶ هدف؛ هر ترکیب پلتفرم و قالب یک‌بار) ← `{ items: [{ contentId, jobId, platform, format }] }`.

- محتوایی که پیش‌نویس تمام‌شده ندارد یا در حال تولید است ← ۴۰۰. نیاز به دسترسی «ویرایش» به موضوع.
- `GET /contents/:id` علاوه بر قبل `source` و `repurposed[]` دارد؛ فهرست و جزئیات `platform` و `sourceContentId` را برمی‌گردانند و `topic.platform` هم هست.
- لاگ ممیزی: `content.repurpose`.
