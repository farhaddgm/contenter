# ثبت کلید AI در پنل مدیریت (docs/62)

ادمین می‌تواند کلید API هر ارائه‌دهنده (Anthropic / OpenAI) را از **تنظیمات ← ارائه‌دهنده‌های AI** ثبت، تعویض یا حذف کند؛ بدون دسترسی به سرور و بدون ری‌استارت.

## رفتار
- کلید با `SecretBox` (AES-256-GCM، کلید مشتق از `DATA_ENCRYPTION_KEY` یا `JWT_REFRESH_SECRET`، purpose `ai-keys`) در `SystemSetting` با کلید `ai-keys` ذخیره می‌شود.
- **اولویت:** کلید ثبت‌شده در پنل از متغیر محیطی (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`) مهم‌تر است. با حذف آن، دوباره کلید محیطی استفاده می‌شود.
- کلید فقط یک‌بار نوشته می‌شود: API و صفحه فقط «متصل/بدون کلید»، منبع (`database` / `env`) و ۴ نویسهٔ آخر را برمی‌گردانند. کلید در لاگ و audit نمی‌آید (audit فقط `set` / `removed`).
- `PUT /api/admin/settings/ai-keys` با `{ provider, key | null }`، فقط ADMIN. پاسخ همان `AiSettingsResponse` است.
- API و worker دو پردازش جدا هستند: API بلافاصله کلید را عوض می‌کند و هر پردازش هر ۱۵ ثانیه `ai-keys` را دوباره می‌خواند (`AiProviderRegistry.refreshKeys`). اگر خواندن شکست بخورد، کلید فعلی می‌ماند.
- اگر کلید ذخیره‌شده باز نشود (کلید رمزنگاری عوض شده)، نادیده گرفته می‌شود و کلید محیطی به کار می‌رود.
- در حالت `AI_PROVIDER=mock` کلید ذخیره می‌شود ولی هیچ درخواستی به ارائه‌دهنده نمی‌رود.
