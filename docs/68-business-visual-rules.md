# قواعد بصری برند (docs/68)

> **وضعیت: طرح و بنچ‌مارک؛ ساخت مشروط.** کدی ساخته نشده. این قابلیت برخلاف بقیه یک **شرط شروع** دارد (بخش ۷). نمای کلی: [65-business-next-steps.md](65-business-next-steps.md).

قواعد دیداری برند به‌صورت داده: پالت رنگ با نقش هر رنگ، قلم‌ها (با علامت پشتیبانی فارسی)، قواعد لوگو، سبک تصویر و رقم‌ها. کد کنتراست رنگ‌ها را بر پایهٔ WCAG می‌سنجد، بلوک `[VISUAL]` برای نوشتن «یادداشت‌های تولید» به مدل می‌رسد، و طراح یک خروجی آماده می‌گیرد.

## ۱. مسئله و وضع فعلی (از کد)

- قواعد بصری فقط متن آزادند: `BRAND_BOOK` («رنگ‌ها، تایپوگرافی، قواعد لوگو/بصری، سیاست هشتگ و ایموجی») و تحلیل دارایی‌ها (`BusinessAssetAnalysisSchema.visualStyle` متن آزاد از مدل).
- **هیچ مصرف‌کنندهٔ بصریِ واقعی ندارد.** محتوا پیوست رسانه ندارد (در `schema.prisma` جدولی برای رسانهٔ محتوا نیست؛ گام ۲۱ نقشهٔ ۵۰ گام ساخته نشده) و تولید تصویر نداریم. تنها خروجی بصری مدل، فیلد `notes` («Production notes: visuals, b-roll, cover text») در خروجی تولید است (`packages/shared/src/ai.ts`).
- کتابخانهٔ پردازش تصویر در API نیست (از وابستگی‌های دیده‌شده فقط `mammoth` برای سند). هر استخراج رنگ سمت سرور وابستگی تازه می‌خواهد.
- قلم فارسی و رقم (فارسی یا لاتین) در گرافیک تصمیم‌های مخصوص بازار ایران‌اند و جایی ثبت نمی‌شوند.

## ۲. ایده‌پردازی

### ۲.۱ ساختار چه باشد؟
| گزینه | مزیت | عیب |
| --- | --- | --- |
| الف) کلید تازهٔ `BusinessSectionKey` (`VISUAL_IDENTITY`، متن) | ساده | باز هم متن آزاد؛ کد نمی‌تواند ببیند |
| ب) **یک ردیف `BusinessVisualRules` با JSON اعتبارسنجی‌شده (Zod)** | ساختار برای کنتراست/خروجی، بدون جدول‌های ریز | JSON رابطه ندارد؛ برای تک‌برند کافی است |
| ج) جدول‌های جدا برای رنگ، قلم، قاعده | انعطاف | ‌سنگین برای داده‌ای که کم و کوچک است |

**انتخاب: ب.** نثر برندبوک در `BRAND_BOOK` می‌ماند؛ این داده فقط چیزهایی است که کد می‌تواند بسنجد یا بفرستد.

### ۲.۲ پالت از کجا بیاید؟
- **دستی** (پایه): ادمین رنگ را با نام و نقش وارد می‌کند.
- **از لوگو در مرورگر**: استخراج رنگ غالب با Canvas سمت مرورگر؛ ادمین از فهرست «پیشنهاد رنگ» انتخاب می‌کند. بدون وابستگی سرور، بدون AI.
- **از سایت (فاز ۲):** متای `theme-color` و متغیرهای CSS با خزندهٔ موجود، اگر `site-parser.ts` سربرگ را نگه دارد (بررسی نشده).
- **از دارایی‌ها با AI (فاز ۳):** کار جدا که از تحلیل‌های `visualStyle` قاعدهٔ پیشنهادی بسازد؛ کد هر `hex` را معتبرسازی می‌کند و نتیجه تأییدنشده می‌ماند.

## ۴. طراحی

### ۴.۱ داده
```prisma
/// قواعد بصری برند (docs/68)؛ یک ردیف برای هر کسب‌وکار
model BusinessVisualRules {
  id           String    @id @default(cuid())
  businessId   String    @unique
  /// VisualRules (packages/shared visual-rules.ts) — اعتبارسنجی با Zod
  rules        Json      @default("{}")
  /// بعد از ویرایش دستی تأییدشده؛ پیشنهاد AI تا تأیید ادمین null
  reviewedAt   DateTime?
  updatedById  String?
  createdAt    DateTime  @default(now())
  updatedAt    DateTime  @updatedAt
  business Business @relation(fields: [businessId], references: [id], onDelete: Cascade)
}
```
`VisualRules` (Zod، حدها با ثابت‌های نام‌دار):
- `palette`: تا ۱۲ رنگ `{ name ≤ 40, hex /^#[0-9a-f]{6}$/i, role: PRIMARY|SECONDARY|ACCENT|NEUTRAL|BACKGROUND|TEXT|WARNING, note }`
- `fonts`: تا ۶ قلم `{ family, role: HEADING|BODY|ACCENT, supportsPersian: boolean, license, url? }`
- `digits`: `FA | LATIN | ANY` (رقم در گرافیک)
- `logo`: `{ assetId?: دارایی از BusinessAsset, minWidthPx?, clearSpace, allowedBackgrounds[], misuse[] }`
- `imagery`: `{ style ≤ 500, do[≤ 8], dont[≤ 8] }`

فایل لوگو همان `BusinessAsset` (نوع `ARTWORK`/`IMAGE`) است؛ فایل در `FileStorageService` می‌ماند و **هرگز در خروجی Docoo/Researcher نمی‌آید** (قاعدهٔ «بدون فایل»).

### ۴.۲ تابع‌های خالص (`packages/shared/src/visual-rules.ts`)
- `contrastRatio(hexA, hexB)` و `wcagLevel(ratio, { large })` ← `AA` / `AA_LARGE` / `FAIL` (آستانه ۴٫۵ و ۳).
- `paletteReport(palette)`: جدول جفت‌های «متن روی زمینه» با نتیجه؛ رنگ‌های بسیار نزدیک؛ هشدار اگر برای `TEXT` یا `BACKGROUND` رنگی نیست.
- `formatVisual(rules)`: بلوک `[VISUAL]` ≤ ۲٬۵۰۰ نویسه؛ `visualToCss(rules)` و `visualToJson(rules)` برای طراح.

### ۴.۳ ورود به پرامپت
بلوک `[VISUAL]` **فقط برای پیش‌نویس** (وقتی `target` هست، مانند `[STYLE]` و `[EXAMPLES]`) و داخل متغیر `business`؛ بدون متغیر تازه و بدون تغییر قالب‌ها. بدون ردیف (یا بازبینی‌نشده)، بایت خروجی همان می‌ماند. تنها `reviewedAt` پرشده خوانده می‌شود (`BusinessApi.visualForPrompt`)، مانند `styleForPrompt`.

### ۴.۴ API و رابط
`GET/PUT /businesses/:id/visual-rules` (`@BusinessScoped`؛ نوشتن EDIT؛ ویرایش = تأیید) و `GET …/visual-rules/export?format=css|json`. برگهٔ «هویت بصری» در صفحهٔ کسب‌وکار: نمونهٔ رنگ، جدول کنتراست (قبول/رد)، فهرست قلم با نشان «فارسی»، کپی/دانلود خروجی. رنگ‌ها فقط نمونهٔ نمایشی داده‌اند؛ رابط خودش از توکن‌های `index.css` می‌خواند، نه از داده‌ٔ برند.

## ۵. قاعده‌ها و قیدها
- AI فقط پیشنهاد می‌دهد (فاز ۳)؛ کنتراست و اعتبار `hex` با کد. خروجی AI تأییدنشده به پرامپت نمی‌رسد.
- هیچ ادعایی دربارهٔ «دسترس‌پذیری کامل» نیست؛ فقط «کنتراست ۲ رنگ» با فرمول WCAG.
- پالت رابط برنامه (توکن‌های عسلی docs/56) به برند کسب‌وکار ربط ندارد و مخلوط نمی‌شود.

## ۶. معیار پذیرش و تست
1. مقدارهای مرجع کنتراست (سیاه/سفید ۲۱:۱، رنگ‌های مرزی ۴٫۵ و ۳) درست؛ `hex` نامعتبر رد می‌شود.
2. بدون ردیف/بازبینی‌نشده، `formatBusiness` بایت‌به‌بایت قبلی است؛ برای جاب‌هایی بدون `target` هیچ‌وقت `[VISUAL]` نیست.
3. بیش از ۱۲ رنگ یا ۶ قلم ۴۰۰؛ بدون EDIT ۴۰۳.
4. خروجی CSS قطعی (ترتیب ثابت) و بدون هیچ فایل یا راز.
5. صادرات Docoo (اگر افزوده شد): فقط داده‌ٔ پالت/قلم، بدون URL امضاشده.

## ۷. ریسک‌ها، شرط شروع و سؤال‌های باز
- **شرط شروع (پیشنهاد):** فقط وقتی بسازیم که (الف) مالک تأیید کند یادداشت‌های تولید/بریف بصری واقعاً به طراح یا ابزار تصویر می‌رسد، یا (ب) گام ۲۱ (پیوست رسانه) شروع شود. وگرنه ارزش آن عمدتاً یک خروجی طراحی و یک جدول کنتراست است که با `BRAND_BOOK` هم پوشش می‌یابد.
- استخراج رنگ از تصویر با ICC یا پروفایل رنگ متفاوت ممکن است خطا بدهد؛ فقط «پیشنهاد» است.
- **سؤال برای مالک:** تصویر و ویدیوی کسب‌وکار را چه کسی/چه ابزاری می‌سازد؟ آیا خروجی `notes` تولید به او می‌رسد؟
