# پلتفرم‌های ایرانی و مستندات رسمی API پیام‌رسان‌ها

> وضعیت: **پلتفرم‌ها اضافه شده‌اند (نسخهٔ ۰٫۲۰٫۰)؛ انتشار خودکار هنوز ساخته نشده.** بخش «مستندات رسمی» نتیجهٔ خواندن صفحه‌های رسمی در ۱۳ اکتبر ۲۰۲۶ (۲۱ مهر ۱۴۰۵) است. هر ادعا با منبع و درجهٔ اعتماد مشخص شده است.

## ۱. چه چیزی ساخته شد

مقدارهای `EITAA`، `BALE`، `RUBIKA`، `APARAT` و `NEWSLETTER` به enum `Platform` اضافه شدند (در `schema.prisma` و `packages/shared/src/enums.ts`، با migration `20261013130000_iranian_platforms`، که فقط مقدار enum اضافه می‌کند).

| پلتفرم | قالب پیش‌فرض بازنشر | نوع رسانهٔ نمونه | تشخیص لینک نمونه |
|---|---|---|---|
| ایتا (`EITAA`) | پست (`POST`) | پست | `eitaa.com`، `eitaayar.ir` |
| بله (`BALE`) | پست | پست | `ble.ir`، `bale.ai` |
| روبیکا (`RUBIKA`) | پست | پست | `rubika.ir` |
| آپارات (`APARAT`) | فیلمنامهٔ ویدیوی بلند | ویدیو | `aparat.com` |
| خبرنامه (`NEWSLETTER`) | خبرنامه | مقاله | ندارد (ایمیل است) |

تقویم، فیلترها، بازنشر، دروازهٔ کیفیت و آمار عملکرد برای این پلتفرم‌ها بدون کار اضافه کار می‌کنند. برچسب‌های فارسی و انگلیسی در `i18n` آمده است.

**چیزی که عمداً ساخته نشد:** هیچ اتصال خودکاری به این پیام‌رسان‌ها نیست. انتشار هنوز دستی است و برنامه فقط ثبتش می‌کند (docs/22).

## ۲. مستندات رسمی (برای ساخت انتشار خودکار)

### بله — [docs.bale.ai](https://docs.bale.ai/) (درجهٔ اعتماد: بالا)

- **آدرس:** `https://tapi.bale.ai/bot<token>/METHOD_NAME` (نام متد حساس به بزرگی حروف نیست). GET و POST، پارامتر با query، `application/x-www-form-urlencoded`، `application/json` یا `multipart/form-data` (برای آپلود).
- **توکن:** از `ble.ir/botfather`؛ به شکل `عدد:رشته`. توکن در مسیر URL می‌آید و هدر احراز هویت جداگانه‌ای وجود ندارد.
- **پاسخ:** JSON با `ok`؛ در موفقیت `result` و در خطا `error_code`، `description` و گاهی `parameters` (مثل `retry_after`).
- **ارسال متن (`sendMessage`):** `chat_id` (عدد، یا `@channelusername` برای کانال) و `text` (۱ تا ۴۰۹۶ نویسه) اجباری؛ `reply_to_message_id` و `reply_markup` اختیاری. پارامتر `parse_mode` در مستندات نیست؛ متن Markdown فرمت می‌شود.
- **رسانه:** `sendPhoto` (کپشن تا ۴۰۹۶)، `sendVideo`، `sendAudio`، `sendDocument` و غیره. حجم: عکس ۵ مگابایت با URL و ۱۰ با آپلود؛ بقیه ۲۰ مگابایت با URL و ۵۰ با آپلود.
- **دریافت:** `getUpdates` یا `setWebhook` (HTTPS روی پورت ۴۴۳ یا ۸۸).
- **API کسب‌وکار (Business):** جداست، پولی (کارمزد برای هر پیام) و فقط چند متد و فقط برای گفت‌وگوی خصوصی. **برای انتشار در کانال مناسب نیست.**
- **کانال:** مستندات صریح نمی‌گویند ربات می‌تواند در کانال پست کند، ولی `chat_id` به‌شکل `@channelusername` و مجوز «ارسال پیام» ادمین کانال در آن‌ها هست. **باید با یک کانال آزمایشی امتحان شود.**

### روبیکا — [rubika.ir/botapi](https://rubika.ir/botapi) (درجهٔ اعتماد: متوسط تا بالا)

- **آدرس:** همه‌چیز `POST https://botapi.rubika.ir/v3/{token}/{method}`. توکن را از `rubika.ir/BotFather` می‌گیرید و در مسیر URL می‌آید.
- **متدها (صفحهٔ methods):**
  - `getMe` بدون ورودی ← `bot`.
  - `sendMessage`: `chat_id`، `text`، `disable_notification`، `reply_to_message_id`، `chat_keypad`، `inline_keypad`، `chat_keypad_type` ← `message_id`.
  - `sendFile`: `chat_id`، `file_id`، `text`، ... ← `message_id`. فایل دو مرحله‌ای است: `requestSendFile` با `type` یک `upload_url` می‌دهد، فایل با `multipart/form-data` در فیلد `file` به آن POST می‌شود و `file_id` برمی‌گردد.
  - `getChat`، `editMessageText`، `deleteMessage`.
- **دریافت:** `getUpdates` (با `start_id`، هر حدود ۵ ثانیه) یا وب‌هوک با `updateBotEndpoint` (دامنهٔ عمومی با HTTPS لازم است).
- **کانال و گروه** (صفحهٔ group-channel): ربات را فقط یک ادمین می‌تواند **دستی** اضافه کند (نه با لینک دعوت) و باید آن را ادمین کند. حداکثر ۱۰ ربات ادمین در هر گروه یا کانال. ربات فقط پیام‌های خودش را در گروه ویرایش می‌کند.
- **مشخص نیست (در صفحه‌هایی که خواندم نیامده):** فرمت `chat_id` کانال، سقف طول متن، سقف حجم فایل، سقف نرخ درخواست و ساختار دقیق پوشش پاسخ (`status`/`ok`). **قبل از ساخت باید با یک کانال آزمایشی سنجیده شود.**

### ایتا — ایتایار [eitaayar.ir](https://eitaayar.ir) (درجهٔ اعتماد: متوسط؛ سند «نسخهٔ آزمایشی» و قدیمی است)

- **چه چیزی است:** ایتا خودش API ربات عمومی ندارد که من پیدا کنم؛ سرویس **ایتایار** (سامانهٔ جدا) یک API برای ارسال به کانال‌ها می‌دهد. سند رسمی آن یک PDF به نام «راهنمای رابط برنامه‌نویسی ایتایار — نسخهٔ آزمایشی» (تاریخ فایل: ۲۰۱۹) است که از `eitaayar.ir/api` دانلود می‌شود. پشتیبانی: `eitaa.com/Yavar`؛ صفحهٔ آزمایش: `eitaayar.ir/testApi`.
- **آدرس:** `https://eitaayar.ir/api/TOKEN/METHOD_NAME`. GET و POST؛ پارامتر با query، JSON، form یا multipart. پاسخ JSON که اولین فیلدش `ok` است (`true`/`false`).
- **توکن:** با ثبت‌نام در eitaayar.ir و از بخش API پنل؛ ربات فرستنده (`@Sender`) باید در کانال یا ابرگروه مدیر شود (طبق راهنمای کتابخانهٔ غیررسمی PyEitaa، نه سند رسمی).
- **متدها:** `getMe`، `sendMessage`، `sendFile`.
  - `sendMessage`: `chat_id` (شناسهٔ کانال در پنل ایتایار، یا نام کاربری کانال بدون `@`) و `text` اجباری؛ `title` (فقط برای پنل)، `disable_notification` (مقدار `1`)، `reply_to_message_id`، `date` (زمان‌بندی؛ Unix timestamp)، `pin` (مقدار `1`)، `viewCountForDelete` (حذف خودکار پس از این‌همه بازدید).
  - `sendFile`: مثل `sendMessage` با `file` (اجباری) و `caption` به‌جای `text`.
- **مشخص نیست:** سقف طول متن و حجم فایل و نرخ درخواست در سند نیست. چون سند قدیمی است، پیش از ساخت باید امتحان شود.
- **بررسی «منبع غیررسمی»:** کتابخانه‌های `PyEitaa`، `eitaaphplib` و `eitaapykit` فقط پوشش همین API هستند و منبع حقیقت نیستند.

### تلگرام — [core.telegram.org/bots/api](https://core.telegram.org/bots/api) (از دانش عمومی، این بار دوباره خوانده نشد)

API ربات رسمی و پایدار است (`sendMessage` تا ۴۰۹۶ نویسه، کپشن رسانه تا ۱۰۲۴). **فعلاً سرور به تلگرام دسترسی مستقیم ندارد** (پاسخ مالک، ۱۳ اکتبر)؛ پس انتشار تلگرام نیاز به پراکسی دارد و در نخستین گام انتشار ساخته نمی‌شود.

### آپارات

برای آپلود ویدیوی آپارات API ربات یا انتشار عمومی پیدا نکردم و بررسی نشد. آپارات فقط برای برچسب، قالب پیش‌فرض و تشخیص لینک اضافه شد.

## ۳. نتیجه برای طراحی انتشار

- هر سه (بله، روبیکا، ایتایار) **توکن در مسیر URL** دارند، پس توکن باید رمزنگاری شده ذخیره شود (`SecretBox`) و در لاگ و پیام خطا هرگز نیاید. لاگ فقط میزبان را نگه دارد (مثل وب‌هوک اعلان‌ها).
- رابط مشترک `MessengerPublisher.send({ chatId, text, media? })` با یک پیاده‌سازی برای هر پیام‌رسان، و آداپتر پشت رابط تا تغییر یکی از آن‌ها بقیه را نشکند (ریسکی که docs/27 هم گفته بود).
- **متن باید با قواعد خود پلتفرم هم‌خوان شود:** بله Markdown می‌خواند؛ برای ایتا و روبیکا قالب‌بندی مستند نیست، پس متن ساده فرستاده شود.
- ایتایار زمان‌بندی خودش را دارد (`date`)، ولی زمان‌بندی را ما انجام می‌دهیم تا بین پلتفرم‌ها یکدست باشد.
- هر سه باید با یک **کانال آزمایشی** امتحان شوند (چیزی که در بالا «مشخص نیست» نوشتم).
