# سبک‌های الهام‌گرفته برای کسب‌وکار (docs/64)

ادمین چند صفحهٔ اینستاگرام و سایت (که **مال خود این کسب‌وکار نیستند**: رقیب، الگو، برند مرجع) را به یک «سبک» می‌دهد؛ AI آن‌ها را می‌خواند و یک **راهنمای سبک** می‌سازد که با هویت **همین کسب‌وکار** سازگار است؛ بعد هر پروژه می‌تواند یکی از سبک‌ها را انتخاب کند و متن‌ها با آن سبک نوشته شوند. هر کسب‌وکار چند سبک با اسم‌های مختلف دارد.

## ۱. اصطلاح‌ها
- **سبک (`BusinessStyle`)**: یک اسم (انتخاب ادمین، یکتا در کسب‌وکار) + «جهت‌دهی» اختیاری ادمین (مثلاً «لحن صمیمی‌شان را بگیر، ادعاهای قیمتی‌شان را نه») + منابع + خروجی ساخته‌شده.
- **منبع سبک (`StyleSource`)**: یک صفحهٔ اینستاگرام، یک سایت (حداکثر ۱۰ صفحه با crawl)، یک صفحهٔ تکی یا یک متن چسبانده. از `BusinessReference` جداست تا **هرگز** به‌عنوان اطلاعات خود کسب‌وکار وارد پروفایل، `[DOCUMENTS]`، خروجی Docoo/Researcher یا بررسی شباهت نشود.
- **خروجی ساخت**: `summary` (چند خط)، `traits` (ویژگی‌های سبک: لحن، ساختار، قلاب آغاز، واژگان، ریتم، قالب‌بندی، ایموجی، CTA، هشتگ، چه چیزی را نگیر)، `guide` (دستور نوشتن، مخصوص همین کسب‌وکار) و `caveats` (محدودیت داده یا ریسک).

## ۲. جریان کار
1. ادمین سبک می‌سازد و اسم می‌دهد (مثلاً «صمیمی مثل فلان‌برند»).
2. منابع را اضافه می‌کند. خواندن در مسیر درخواست و **با کد** است (بدون AI)؛ نتیجه یک snapshot متنی است که ادمین می‌بیند و می‌تواند تازه کند.
3. «ساخت سبک» یک job `BUSINESS_STYLE_BUILD` می‌گذارد؛ runner منابع را همراه پروفایل کسب‌وکار به مدل می‌دهد و خروجی schema-validated را ذخیره می‌کند (`buildState` = `READY`).
4. خروجی AI تا تأیید ادمین **بازبینی‌نشده** است (`reviewedAt` = null). ادمین می‌خواند، `summary` / `guide` را ویرایش می‌کند (ویرایش دستی = تأیید) یا «تأیید» می‌زند.
5. در تنظیمات پروژه سبک انتخاب می‌شود (`Topic.styleId`، فقط سبک تأییدشدهٔ همان کسب‌وکار). حذف سبک، پروژه را بدون سبک می‌گذارد.
6. در نوشتن پیش‌نویس (`GENERATE_CONTENT`، `REPURPOSE_CONTENT`) بلوک `[STYLE]` داخل متغیر `business` می‌آید؛ **متغیر پرامپت تازه نداریم** و بایت‌های پرامپت بدون سبک تغییر نمی‌کند.

## ۳. قواعد
- **تقلید سبک، نه کپی متن.** مدل فقط الگو را توصیف می‌کند؛ نقل مستقیم بیش از چند کلمه از منبع ممنوع است. در `guide` نمونهٔ آماده از متن رقیب نمی‌آید.
- **هویت کسب‌وکار همیشه مقدم است**: facts، اصطلاحات و `register` از سبک قوی‌ترند؛ پرامپت این اولویت را صریح می‌گوید. ادعاها (قیمت، گارانتی، آمار) از منبع به متن نمی‌آیند.
- **اینستاگرام:** هرگز instagram.com واکشی نمی‌شود (docs/28). خواندن حساب فقط با Graph API (Business Discovery؛ نیازمند `INSTAGRAM_GRAPH_TOKEN` و `INSTAGRAM_GRAPH_USER_ID`) یا دادهٔ دستی (`instagram` در ورودی منبع). آمار با `analyzeInstagram` (کد) حساب می‌شود و مدل فقط تفسیر می‌کند. نظرات و دنبال‌کننده‌ها خوانده/ذخیره نمی‌شوند.
- **سایت:** همان crawler (robots.txt، حداکثر ۱۰ صفحه). برخلاف رفرنس‌های خود کسب‌وکار، میزبان مشترک رد نمی‌شود مگر صفحهٔ ورود (`isLoginWall`) باشد که ذخیره نمی‌شود.
- **مجوز:** فقط کسی که به کسب‌وکار EDIT دارد می‌سازد/ویرایش می‌کند (`@BusinessScoped`)؛ خواندن با VIEW. سبک‌ها در پاسخ‌های خارجی (Docoo/Researcher) **نیستند**.
- حدها: ≤ ۸ سبک برای هر کسب‌وکار، ≤ ۶ منبع برای هر سبک (`BUSINESS_STYLE_LIMIT`، `STYLE_SOURCE_LIMIT`).
- بازسازی سبک نتیجهٔ قبلی را جایگزین می‌کند و تأیید را برمی‌دارد.

## ۴. داده
- `BusinessStyle`: `businessId`, `name` (unique با business), `direction`, `buildState` (`NONE/BUILDING/READY/FAILED`)، `buildError`, `lastJobId`, `summary`, `traits Json`, `guide`, `caveats String[]`, `builtAt`, `reviewedAt`, `createdById`.
- `StyleSource`: `styleId`, `kind` (`INSTAGRAM/WEBSITE/URL/TEXT`)، `url`, `title`, `content`, `analysis Json?`, `status` (`ReferenceStatus`)، `error`, `fetchedAt`.
- `Topic.styleId` (nullable، `onDelete: SetNull`).
- Task تازه: `BUSINESS_STYLE_BUILD` (heavy در `AI_TASK_WEIGHT`؛ خارج از economy چون خروجی را ادمین منتظر است).

## ۵. API (همه زیر `@BusinessScoped`)
| مسیر | کار |
| --- | --- |
| `GET /businesses/:id/styles` | فهرست (بدون متن منابع) |
| `POST /businesses/:id/styles` | ساخت `{ name, direction? }` |
| `GET /business-styles/:id` | جزئیات + منابع |
| `PATCH /business-styles/:id` | `name`, `direction`, `summary`, `guide` (ویرایش `summary`/`guide` = تأیید) |
| `DELETE /business-styles/:id` | حذف |
| `POST /business-styles/:id/sources` | افزودن منبع (لینک / `site` / متن / `instagram` دستی) |
| `POST /style-sources/:id/refresh`، `DELETE /style-sources/:id` | تازه‌سازی / حذف |
| `POST /business-styles/:id/build` | job ساخت |
| `POST /business-styles/:id/review` | تأیید |
| `PATCH /topics/:id` با `styleId` | انتخاب سبک پروژه |

## ۶. رابط کاربری
- صفحهٔ کسب‌وکار: برگهٔ «سبک‌ها» (فهرست با نام، وضعیت ساخت، تأییدشده/نشده؛ دیالوگ ساخت؛ جزئیات با منابع، دکمهٔ ساخت/بازسازی، ویرایش راهنما، تأیید).
- تنظیمات پروژه: انتخاب «سبک نوشتن» (فقط سبک‌های تأییدشده).
- متن‌ها از `i18n/fa.ts`؛ کلاس‌های منطقی RTL؛ رنگ فقط از توکن‌ها؛ اکشن اصلی `PageHeader` اول.

## ۷. نکته‌های ساخت و محدودیت
- بودجه‌ی متن منابع: سهم مساوی برای هر منبع در ≤ ۶۰ هزار نویسه؛ مازاد با `[truncated]`.
- `traits` تا ۱۴ مورد، `guide` تا ۳٬۰۰۰ نویسه، `caveats` تا ۶ مورد.
- ساخت بدون منبع READY ممکن نیست (400).
- مرز ماژول (docs/63): جدول‌های `BusinessStyle`/`StyleSource` جزو هویت کسب‌وکارند؛ بیرون از `modules/businesses` فقط از `BusinessApi.styleForTopic` خوانده می‌شوند و runner در فهرست استثنای ESLint است.
