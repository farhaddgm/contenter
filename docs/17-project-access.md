# دسترسی به موضوع‌ها (پروژه‌ها)

هر موضوع (پروژه) فقط برای کسانی باز است که اجازه دارند. مدیر برای هر کاربر تعیین می‌کند به کدام موضوع دسترسی داشته باشد و در هر موضوع فقط ببیند یا ویرایش هم بکند.

## چه کسی چه می‌بیند

| کاربر | موضوع‌هایی که می‌بیند | نوع دسترسی |
|---|---|---|
| **مدیر** (از جمله مالک) | همهٔ موضوع‌ها | ویرایش |
| **ویرایشگر / مشاهده‌گر** | موضوع‌هایی که خودش ساخته | ویرایش (مگر اینکه مدیر آن را «فقط مشاهده» کرده باشد) |
| | موضوع‌هایی که مدیر به او داده | همان که مدیر تعیین کرده: «فقط مشاهده» یا «ویرایش» |
| | بقیهٔ موضوع‌ها | هیچ؛ در فهرست‌ها هم دیده نمی‌شوند |

- نوع دسترسی **برای هر موضوع جداگانه** تعیین می‌شود و بر نقش کلی کاربر مقدم است. یعنی مشاهده‌گری که در یک موضوع «ویرایش» گرفته، در همان موضوع می‌تواند ویرایش کند. ویرایشگری هم که «فقط مشاهده» گرفته، در آن موضوع فقط می‌بیند.
- نقش کلی همچنان این‌ها را تعیین می‌کند: ساختن موضوع تازه (فقط ویرایشگر و مدیر)، کار روی کسب‌وکارها، و بک‌آفیس (فقط مدیر). حذف موضوع هم مثل قبل فقط کار مدیر است.
- دسترسی‌های داده‌شده بلافاصله اعمال می‌شوند و لازم نیست کاربر دوباره وارد شود.

## مدیریت دسترسی‌ها

در **بک‌آفیس ← کاربران**، کنار هر ویرایشگر یا مشاهده‌گر دکمهٔ **«دسترسی به موضوع‌ها»** (آیکون پوشه و کلید) هست. پنجرهٔ آن همهٔ موضوع‌ها را نشان می‌دهد و برای هر کدام این گزینه‌ها را دارد:

- **بدون دسترسی**: موضوع برای این کاربر دیده نمی‌شود.
- **فقط مشاهده**: همه‌چیز را می‌بیند، ولی دکمه‌های ساخت، ویرایش و تولید برایش نمایش داده نمی‌شوند و API هم جلوی تغییر را می‌گیرد.
- **ویرایش**: مثل سازندهٔ موضوع کار می‌کند.

موضوع‌هایی که خود کاربر ساخته با برچسب «سازنده» مشخص شده‌اند. برای این موضوع‌ها «بدون دسترسی» وجود ندارد، ولی می‌توان آن‌ها را «فقط مشاهده» کرد. هر تغییر در لاگ ممیزی با `topic_access.set` ثبت می‌شود.

> این بخش برای همهٔ مدیرها باز است؛ مالک هم مدیر است. مدیرها به دسترسی جداگانه نیاز ندارند.

## نکتهٔ انتشار

بعد از انتشار این نسخه، ویرایشگرها و مشاهده‌گرها **فقط موضوع‌هایی را می‌بینند که خودشان ساخته‌اند**. موضوع‌های دیگری را که باید ببینند، از همین پنجره به آن‌ها بدهید.

## جزئیات فنی

- جدول `TopicMember` (`topicId`, `userId`, `access: VIEW | EDIT`). سازنده بدون ردیف، دسترسی `EDIT` دارد و ردیف صریح بر آن مقدم است (`accessOf` در `apps/api/src/common/topic-access.ts`).
- هر route وابسته به موضوع با `@TopicScoped(via, param)` علامت خورده است. `TopicAccessGuard` موضوعِ رکورد را پیدا می‌کند (sample، idea، content، profile، trait، brandDoc، principle). نبودِ دسترسی ‎404 برمی‌گرداند و «فقط مشاهده» برای تغییر ‎403. نیاز پیش‌فرض: `GET` → `VIEW`، بقیه → `EDIT`. روی این routeها، قاعدهٔ کلیِ «مشاهده‌گر فقط GET» در `RolesGuard` اعمال نمی‌شود.
- فهرست‌ها با `TopicAccessService.visibleWhere()` فیلتر می‌شوند: فهرست موضوع‌ها، فهرست محتواها، داشبورد (آمار و کارهای AI)، و موضوع‌های متصل در صفحهٔ کسب‌وکار. `GET /jobs/:id` هم برای کار وابسته به موضوع، دسترسی مشاهده می‌خواهد.
- پاسخ موضوع فیلد `access` دارد و وب با `useCanEditTopic(topicId)` دکمه‌های تغییر را نشان می‌دهد یا پنهان می‌کند.
- API مدیر: `GET /api/admin/users/:id/topics` و `PUT /api/admin/users/:id/topics/:topicId` با بدنهٔ `{ access: 'VIEW' | 'EDIT' | null }`.
- **route تازه‌ای که به یک موضوع مربوط است، باید `@TopicScoped` داشته باشد.** فهرست تازه‌ای هم که موضوع‌ها یا داده‌های آن‌ها را برمی‌گرداند، باید `visibleWhere` را اعمال کند.
